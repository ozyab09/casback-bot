# ТЗ: бот «Мой Кэшбэк» (Telegram Mini App)

Версия: 1.0 · Дата: 2026-10-20
Стек: платформа tgcloud (serverless-модули в `tgcloud/`) + React/Vite Mini App.
Референс: приложение «Мой Кэшбэк» v2.0 (учёт категорий и % кэшбэка карт разных банков со справочником MCC).

---

## 1. Суть продукта

Личный помощник для выбора карты при оплате. Пользователь заводит свои банки
и карты, для каждой категории кэшбэка указывает процент и список MCC-кодов
(кодов торговых точек). Приложение по MCC/названию точки отвечает: **какой
картой платить выгоднее** и сколько составит кэшбэк.

Бот в Telegram — точка входа (`/start` открывает Mini App). Вся основная
логика и хранение — в Mini App + эндпоинтах + БД.

## 2. Акторы и границы

| Актор | Права |
|---|---|
| Владелец (в Telegram) | CRUD своих банков, карт, категорий, точек; поиск; экспорт/импорт |

Данные строго изолированы по пользователю (`ctx.initData.user.id`). Никакого
шаринга, друзей, рефералок — в MVP нет. Все данные доверяем только
верифицированному `initData`; ничего присланного клиентом не считаем
доверенным без проверки владения записью.

## 3. Функциональные требования

### 3.1 Банки
- CRUD банков: название (уникальное в пределах пользователя).
- Удаление банка каскадом удаляет его карты и категории (в коде: no-FK платформа).

### 3.2 Карты
- Карта: банк, название, владелец, последние 4 цифры (для различения карт одного банка), месячный лимит по категории (опционально), заметка.
- Несколько карт одного банка — поддерживаются.

### 3.3 Категории кэшбэка
- Категория принадлежит банку и содержит: название, базовый процент,
  список MCC-кодов (из справочника) и MCC-исключения.
- MCC подставляется автоматически при выборе названия из встроенного
  справочника (см. 3.5); пользователю можно вводить MCC и вручную.
- Категория «Все покупки» (MCC = `*`) — неявный fallback: применяется, когда
  ни одна спецкатегория не подошла; не отображается, если есть исключения.

### 3.4 Поиск «чем платить» (главная функция)
Ввод: число MCC **или** текст (название точки → MCC через справочник и
личные точки).
Вывод по каждой подходящей карте:
- категория и процент, расчёт кэшбэка по введённой сумме (опционально),
- «выгоднее всех» подсвечен максимальным процентом,
- указание лимитов («осталось 3 400 ₽ в этой категории»),
- «Все покупки», если спецкатегории нет.

### 3.5 Справочник MCC (read-only, поставляется с приложением)
- Seed-данные в проекте (`tgcloud/lib/mccRef.js`), заливаются в таблицу
  `mcc_ref` при миграции/первом запуске официального скрипта из `tgcloud/`.
- Наполнение — по логическому смыслу (как у референса v2.0); редактирование
  справочника пользователем недоступно; свои уточнения кладутся в личные
  категории/точки.

### 3.6 Торговые точки (личные)
- `точка = название + MCC + заметка`. Используются для быстрого поиска по
  тексту, когда MCC отсутствует в справочнике.

### 3.7 Импорт / экспорт
- Экспорт: JSON всех данных пользователя (банки → карты/категории, точки),
  скачивается из Mini App.
- Импорт: валидация структуры, замена или слияние (режим выбирается в UI).
- Полная совместимость формата со справочником v2.0 не требуется — фиксируем
  **свой** JSON-формат (schema в разделе 6).

### 3.8 Бот (handler `handlers/message`)
- `/start` → приветствие + кнопка-кнопка с WebApp (open Mini App).
- `/help` → краткая шпаргалка по возможностям.
- Прочее — подсказка, что всё делается в Mini App (без диалоговых сценариев в MVP).

## 4. Экраны Mini App (SPA)

1. **Главная / поиск** — большое поле ввода (сумма + MCC/точка), выдача «чем платить».
2. **Карты** — список карт с их лучшими категориями; карточка карты → редактирование.
3. **Категории банка** — редактор категории: процент, MCC-список с автоподстановкой, исключения.
4. **Точки** — список личных точек, CRUD.
5. **Настройки** — экспорт/импорт JSON.
Навигация — вкладки Telegram.WebApp (`BackButton` на вложенных экранах).

## 5. Нефункциональные требования и правила платформы

- **Данные:** schema.js — единый файл, таблицы — named exports; **без FK**
  (целостность в коде: перед удалением родителя удалять потомков).
- **Эндпоинты:** `tgcloud/endpoints/<name>.js`, POST `/api/<name>`;
  отказ через `throw new EndpointError(...)` → `400`; `ctx.initData` даёт
  верифицированного пользователя.
- **Фронт:** обычный SPA на React + Vite, `base: '/'`, сборка `dist`;
  `tgcloud.jsonc` → `{ "static": { "source": "dist", "spa": true } }`.
  Без `X-Frame-Options`/жёсткого `frame-ancestors`.
- **Клиент → бэк:** только `Telegram.WebApp.Serverless.call(...)`
  (`telegram-web-app.js`); никакого ручного `fetch` с initData.
- **Тесты модулей:** `npx tgcloud run endpoints/<name> '{...}' --ctx '{ initData: { user: { id: 1 } } }'`.
- **Деплой:** `npm run deploy` (сборка фронта + push); изменения schema →
  отдельный `npx tgcloud migrate` (интерактивно).
- Push-напоминания по расписанию недоступны на платформе — не закладывать.

## 6. Модель данных (tgcloud/schema.js)

| Таблица | Ключевые поля |
|---|---|
| `users` | `id` (tg_user_id), `username`, `created_at` |
| `banks` | `id`, `user_id`, `name`, created_at |
| `cards` | `id`, `user_id`, `bank_id`, `name`, `last4`?, `holder`?, `monthly_limit`?, `note`? |
| `categories` | `id`, `user_id`, `bank_id`, `name`, `percent` (basis), `mcc_codes` (массив), `excluded_mcc` (массив), `note`? |
| `places` | `id`, `user_id`, `name`, `mcc`, `note`? |
| `mcc_ref` | `mcc` (PK), `title` — seed справочник |
| `app_meta`? | версия формата экспорта (можно константой в коде) |

Индексы: `banks(user_id)`, `cards(user_id, bank_id)`, `categories(user_id, bank_id)`, `places(user_id)`, `mcc_ref(mcc)`.

Формат экспорта (константа `SPEC_VERSION = 3` в `lib/export.js`):
```json
{ "spec": 3, "user": "<tg_id>", "banks": [
    { "name": "...", "cards": [ { "name": "...", "last4": "1234", "holder": "...", "monthlyLimit": 50000, "note": "" } ],
      "categories": [ { "name": "...", "percent": 5, "mcc": [5300, 5411], "excluded": [4829], "note": "" } ] } ],
  "places": [ { "name": "...", "mcc": 5300, "note": "" } ] }
```

## 7. Эндпоинты (эскиз таблицей)

| Эндпоинт | Вход | Выход |
|---|---|---|
| `getOverview` | `{}` | банки/карты/категории/точки одним пакетом (для первой загрузки SPA) |
| `saveBank` / `deleteBank` | `{id?|name}` / `{id}` | обновлённая сводка |
| `saveCard` / `deleteCard` | карточка / `{id}` | обновлённая сводка |
| `saveCategory` / `deleteCategory` | категория / `{id}` | обновлённая сводка |
| `savePlace` / `deletePlace` | точка / `{id}` | обновлённая сводка |
| `search` | `{ query, amount? }` | варианты раскладки «чем платить» |
| `exportData` / `importData` | `{}` / JSON по разделу 6 | JSON / сводка |

Все эндпоинты возвращают обновлённую «сводку» после мутаций — SPA один раз
ждёт ответ и не гоняет лишние запросы.

## 8. Приёмочные критерии

1. `/start` открывает Mini App; initData верифицируется платформой (нечестный вызов → 401, эндпоинт не выполняется).
2. Чужой пользователь не читает и не изменит чужие записи (проверка ownerId в каждом эндпоинте).
3. Поиск `5300`/«супермаркет» даёт корректные проценты по картам; корректно работает fallback «Все покупки»; учитываются исключения и лимиты.
4. Удаление банка не оставляет висячих карт/категорий.
5. Экспорт/импорт туда-обратно восстанавливает идентичные данные.
6. `npm run deploy` собирает фронт и разворачивает статику + модули без ручных правок.

## 9. Вне MVP (зафиксировать «потом»)

- Парсинг чеков по QR / ФНС-апи (требует внешнего сервиса и ключей).
- Пуш-напоминания («повышенный кэшбэк сегодня» — нет крона на платформе).
- Мульти-язычность, шаринг расчётов, взаиморасчёты, веб-версия без Telegram.

## 10. Этапы работ

1. schema.js + seed MCC-справочника + миграция (`npx tgcloud migrate`).
2. `lib/` (валидация, поиск, экспорт) + эндпоинты; локальные прогоны `npx tgcloud run`.
3. Handler `/start`, `/help` — проверка `tgcloud webhook`.
4. React/Vite-фронт `front/` (или `web/`), вкладки, дизайн по разделу 4.
5. Приёмочные проверки по разделу 8, затем `npm run deploy`.
